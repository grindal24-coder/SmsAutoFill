# SMS AutoFill Demo (фоновый режим)

Android-проект на Kotlin: приложение можно **полностью закрыть**, и при
приходе SMS с кодом всё равно всплывёт попап с предложением вставить код
— поверх любого другого приложения (мессенджера, банка и т.д.).

Google Play Services **не используются** — это работает даже на
устройствах без GMS.

## Как это устроено

- `RECEIVE_SMS` — разрешение, которое приложение один раз запрашивает
  через экран `MainActivity`.
- `SmsReceiver` зарегистрирован **в манифесте** (не динамически) — Android
  доставляет ему SMS даже если процесс приложения не запущен, и сам
  временно поднимает процесс на время обработки.
- Как только в тексте SMS находится код (регулярка `\b\d{4,6}\b`),
  `SmsReceiver` синхронно запускает `CodePopupActivity` — это официально
  разрешённое исключение из ограничений на запуск экрана из фона в
  Android, поэтому попап всплывает даже поверх других приложений.
- `CodePopupActivity` — прозрачная диалоговая Activity с кнопками
  "Вставить" / "Отклонить". "Вставить" копирует код в буфер обмена (сам
  напечатать текст в чужом приложении технически невозможно — для этого
  нужен отдельный Accessibility Service).

## Как собрать APK на GitHub

1. Создайте пустой репозиторий на github.com.
2. В папке проекта:
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПО.git
   git push -u origin main
   ```
3. Вкладка **Actions** → сборка запустится сама при пуше в `main`.
4. В конкретном workflow run → раздел **Artifacts** → скачайте
   `sms-autofill-debug-apk`.

## После установки на телефон

1. Откройте приложение один раз, нажмите "Разрешить чтение SMS".
2. Нажмите "Снять ограничения батареи" и подтвердите.
3. На Xiaomi/Huawei/Honor и похожих прошивках дополнительно разрешите
   "Автозапуск" для приложения в настройках батареи/приложений —
   иначе система может убивать фоновые процессы агрессивнее стандартного
   Android.
4. Приложение можно закрыть — при приходе SMS с кодом попап появится сам,
   даже поверх других открытых приложений.

## Ограничение, о котором важно знать

Это решение не может **автоматически напечатать** код в поле стороннего
приложения (Android не даёт одному приложению трогать UI другого) — код
копируется в буфер обмена, и пользователю нужно один раз вставить его
вручную. Полностью автоматическая вставка без единого нажатия возможна
только через Accessibility Service — это отдельная, более тяжёлая
доработка с ручной активацией разрешения в настройках.
